# 00007 — The theme audit reports a redefinition the theme's own reads never see

> Status: **approved 2026-10-22**. Supersedes nothing. Built on plan 00006's model of Avalonia's resource lookup.

An application that redefines one of its theme's keys expects the theme's controls to change, and under
Avalonia 12.1.3 they often do not. Semi's controls read component tokens such as
`ButtonSolidPrimaryBackground`, and such a token is a `StaticResource` alias, inside Semi, of a palette key
such as `SemiColorPrimary`. The alias resolves through Semi's own dictionaries before the application's, so
redefining `SemiColorPrimary` in `App.axaml` leaves every Semi button as it was, though
`Application.TryGetResource` returns the redefinition. The WPF-to-Avalonia port measured that on 2026-10-15,
and `docs/avalonia-gotchas.md` holds it. The developer held a check for it on 2026-10-19 until someone read how
such an alias resolves; the port read it in the source on 2026-10-20, and the developer asked for this plan the
same day, the audit's model corrected first.

Plan 00006 corrects the model. The walk keeps each dictionary with the chain it was loaded in, and the lookup
follows an alias where Avalonia does, each of its rules drawn headless, so the audit can already say where a
read resolves. What it lacks is a reading of the theme's own references, static apart from dynamic, and of
where a consumer defines a key, beyond the key itself.

## What the audit reads, with plan 00006

- `ThemeGraphWalker` builds each dictionary a theme loads, with the chain it was loaded in, and
  `ResourceApplication` looks a key up as an application holding the theme in its styles does. A static alias
  searches its own chain, then the application, in the variant of the theme dictionary around it; a dynamic one
  searches the application under the variant asked; and a dictionary with a class of its own, entered by its
  element, is a root built at once, which reaches no application the audit can see. All of it is internal.
- Every theme alias, static or dynamic, is one `ResourceValue.Alias`, and
  `ThemeDefinitionScanner.ReadsDynamically` tells the two apart from `ResourceDefinition.Element`.
- Nothing reads a theme's control themes, styles or templates for the keys they reference.
  `ResourceReferenceScanner`, which keeps static and dynamic apart, runs over consumers only.
- A consumer's definitions survive only as key strings, `ConsumerScan.OwnKeys`. `ThemeDefinitionScanner` reads
  each one's file, line and variant, and `AuditRunner` drops them.
- The resources a control theme, a style or a template holds are read as their dictionary's own entries,
  though Avalonia scopes them to it; the runtime check's `OnlyInControlTheme` pins that gap.

### Dismissed

- **Asking the running application.** `RuntimeCheckPlan` asks `Application.TryGetResource`, which returns
  the redefinition, the very answer that misleads. Only drawing the theme's controls shows the miss.
- **Building the check on the audit's model as it stood.** It flattened a theme and its `merge` files into one
  map, so a key a `merge` file redefined reached the theme's aliases in the audit's colours, where Avalonia does
  not follow it. By the developer's decision of 2026-10-20, plan 00006 corrects the model first.
- **Reading only aliases and brushes, as plan 00006 drew them.** It would miss a key a theme reads only in a
  setter, as Semi's `TextBox` reads its context flyout; decision 8 draws the other kinds instead, by the
  developer's decision of 2026-10-22.
- **Reporting a redefinition some reads see and others miss.** It changes something the theme draws, so it
  is not the trap, and such rows would bury the ones that are.
- **Reporting a redefinition the theme never reads.** The application's own reads see it.
- **Reading where in a consumer a key is defined, the application's resources or a window's.** It would only
  recover findings that a window's definition hides, where a read reaches the application and not the window, or
  an entry of the theme's is replaced in the window alone; no configuration says which of a consumer's files the
  application loads.
- **A switch that turns the check off for a consumer that is not an application.** Each such finding is true
  for an application that holds the consumer's files, and the switch would be configuration, permanent once
  released, for one consumer's convenience, by the developer's decision of 2026-10-22.
- **A rule instead of an audit check.** A rule knows no theme; the audit pairs each consumer with its themes.
