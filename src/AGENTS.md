# AGENTS.md — `src/`

The three shipped projects. All three are packed and published from one tag, so everything here is
permanent once released. There is no `src/Directory.Build.props`; every project takes the root one
directly.

| Project | Assembly | Package | What it ships |
|---|---|---|---|
| `XamlQuality/` | `XamlQuality` | `Bennewitz.Ninja.XamlQuality` | The rules (`Rules/`, each an `IXamlRule`), the scan model (`XamlScanContext`, `XamlFile`, `XamlFinding`, `XamlSkip`), and the whole `ThemeAudit` analysis with its reviewed `ThemeAudit/Mappings/*.json` |
| `XamlQuality.ThemeAudit/` | `ThemeAudit` | `Bennewitz.Ninja.XamlQuality.ThemeAudit` | The `theme-audit` dotnet tool: `Program.cs`, argument parsing and reporting over the library's `ThemeAudit` namespace, and nothing else |
| `XamlQuality.ThemeRuntime/` | none shipped | `Bennewitz.Ninja.XamlQuality.ThemeRuntime` | The runtime theme check's Avalonia half as source, `ThemeRuntimeCheck.cs` and `ThemeRuntimeMap.cs`, packed as compile content that an Avalonia test project compiles against its own Avalonia; it depends on the library at a minimum of its release. The project compiles none of the files |

## Rules

| Rule | Why | Guarded by |
|---|---|---|
| `XamlQuality.csproj` takes no `PackageReference`; `System.CommandLine` belongs to the tool alone | The library's dependencies become every consumer's test-project dependencies | `Directory.Packages.props`, group `Tool`; `AssemblyQualityTests.BNAQ1003_no_assembly_references_a_framework_or_another_family_package`, whose `ForbiddenInTheLibraryOnly` names `System.CommandLine` |
| Analysis goes in the library, never in `Program.cs` | A consumer's test project runs the same analysis without shelling out to the tool | `XamlQuality.ThemeAudit.csproj`, `Description` |
| The tool's `AssemblyName` stays `ThemeAudit` and its `ToolCommandName` stays `theme-audit` | `InternalsVisibleTo("ThemeAudit")` is how the tool reaches `ResourceKeyScanner` and `ResourceKey`; the command name is what consumers' scripts and CI steps invoke | `src/XamlQuality/Properties/AssemblyInfo.cs`; `XamlQuality.ThemeAudit.csproj` comment on `ToolCommandName` |
| `Properties/AssemblyInfo.cs` names which `ThemeAudit` types are public and which stay internal | The audit surface shipped public and a consumer binds to it, so narrowing a type is a breaking change | `src/XamlQuality/Properties/AssemblyInfo.cs` comment |
| Every public member carries an XML doc comment | `GenerateDocumentationFile` is on in the library's and the tool's csproj files and warnings are errors, so a missing comment fails the build | `XamlQuality.csproj`, `XamlQuality.ThemeAudit.csproj`; root `Directory.Build.props`, `TreatWarningsAsErrors` |
| The source-only project's files compile in any adopting project: each starts `// <auto-generated/>` and `#nullable enable`, has no using directive, names every type outside it from `global::`, and declares every type `internal` | An adopting project may turn implicit usings off, declare global aliases of its own, and build with warnings as errors and analyzers of its own; and this project, which has no Avalonia, compiles none of them | `SourceOnlyPackageTests`; `tests/XamlQuality.ThemeRuntime.Tests`, which compiles them as such a project would |
| The `None` item for `ThemeAudit/Mappings/*.json` keeps `Link`, `PackageCopyToOutput` and `PackagePath` | `CompatMapping.Locate` resolves a bare mapping name against `Mappings/` beside the assembly; without them a `PackageReference` consumer gets no files there | `XamlQuality.csproj`, the comments on that item |
| `theme-audit` exits 0 when clean, 1 on drift or an unreadable file, 2 on a configuration error; every `--check` runs the library's drift check, `OutputDrift.Check`, and every output is written through `OutputDrift.Write`, which removes the received copy a stale check left | CI steps in consuming repositories branch on the code, and a check written again in `Program.cs` would compare differently from a consumer's test | `Program.cs`, the `compat`, `report` and `parts` actions; `tests/XamlQuality.Tests/ThemeAudit/ThemeAuditToolTests.cs` |
| A project added here is also referenced from `tests/XamlQuality.Tests/XamlQuality.Tests.csproj`, a source-only one with `ReferenceOutputAssembly` false, and named in `release.yml` | `AssemblyQualityTests` scans every csproj under `src` but a source-only one and fails when its assembly is not in the test output; `SourceOnlyPackageTests` packs a source-only one without a build, which restores nothing, so the reference is what readies it; the release publishes only the packages it names | `AssemblyQualityTests.Every_shipped_assembly_is_in_the_scan`; `SourceOnlyPackageTests.Each_packs_without_a_build`; `ReleaseWorkflowTests` |
